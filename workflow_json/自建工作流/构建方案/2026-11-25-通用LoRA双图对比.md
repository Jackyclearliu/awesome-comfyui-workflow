# 通用 LoRA 双图对比工作流实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 生成 MOSS、Krea2、Qwen Image 2.1 共用的单分支切换、原模型/LoRA 双图对比工作流，并完成三条分支的低负载实际出图验证。

**Architecture:** 一个 ComfyUI UI JSON 文件包含三条独立模型分支；每条分支由 LoRA Manager 加载器、共享提示词编码、两个采样与解码链、两个保存节点和一个比较预览节点组成。默认只启用 Krea2 Turbo，其他分支通过节点禁用状态隔离。

**Tech Stack:** ComfyUI UI workflow JSON、ComfyUI-Lora-Manager、Goohaitools-comfyui、本机 ComfyUI Python venv、ComfyUI HTTP `/object_info` 与 `/prompt` API。

## Global Constraints

- 交付路径固定为 `workflow/workflow_json/自建工作流/通用LoRA双图对比_MOSS_Krea2_QwenImage2.1.json`。
- 默认 1024×1024、批次 1、固定种子，LoRA 强度 1.0；不修改官方模板和插件源码。
- 两次采样使用完全相同的最终提示词、种子和采样参数，唯一差异是 MODEL 是否经过 LoRA 加载器。
- `GH_ImageVideoComparer` 仅用于预览；图像仍由 LoRA Manager 保存节点输出。
- 验证使用 256×256、1 步，且不得把验证参数写回交付文件。
- 验证结束后必须关闭本次启动的 ComfyUI 进程并清理临时文件。
- 不执行 git commit，不处理仓库中与本任务无关的既有改动。

### Task 1: 核对运行时节点契约

**Files:**
- Read: `custom_nodes/ComfyUI-Lora-Manager/py/nodes/lora_loader.py`
- Read: `custom_nodes/Goohaitools-comfyui/nodes/图像对比 视频对比.py`
- Read: 三个官方 T2I JSON 模板
- Temporary: 独立临时目录中的 `object_info.json` 与启动日志

**Interfaces:**
- Consumes: 本机模型目录、插件注册表、官方模板节点配置。
- Produces: 每条分支的节点注册名、输入顺序、widget 顺序、模型文件名及 LoRA 空选择行为。

- [ ] **Step 1: 检查 LoRA Manager 加载器实现**

定位 `Lora Loader (LoraManager)`、`Save Image (LoraManager)` 的注册名和执行函数，记录 `model/text/loras` 的格式、空 LoRA 列表是否原样返回 MODEL、触发词输出格式，以及保存节点必填 widget。

- [ ] **Step 2: 检查比较节点实现**

定位 `GH_ImageVideoComparer` 的两个图像输入名称和顺序，确认它没有数据输出，不能作为保存节点的上游。

- [ ] **Step 3: 启动临时实例并保存运行时定义**

Run:

```bash
./venv/Scripts/python.exe main.py --port 8199 --listen 127.0.0.1
```

请求 `http://127.0.0.1:8199/object_info` 并保存到独立临时目录。若 8199 已被占用，使用 8201；不得终止已有进程。

- [ ] **Step 4: 校验模型与节点契约**

用 Python JSON 断言确认所需注册名全部存在，CLIP 类型分别为 `moss_image`、`krea2`、`qwen_image`，三个 UNET、三个文本编码器和对应 VAE 文件都在选项中。若 MOSS 本机编码器名称与官方模板不同，以 `/object_info` 和模型目录共同确认实际文件名。

### Task 2: 生成画布工作流

**Files:**
- Create: `workflow/workflow_json/自建工作流/通用LoRA双图对比_MOSS_Krea2_QwenImage2.1.json`
- Reference: `docs/superpowers/specs/2026-11-25-universal-lora-comparison-design.md`

**Interfaces:**
- Consumes: Task 1 的运行时节点契约。
- Produces: 可导入 ComfyUI 的 UI workflow JSON，包含唯一节点 ID、唯一链接 ID、分组、说明节点和三条完整分支。

- [ ] **Step 1: 建立共享控制与说明区**

创建固定种子、提示词、宽高控制及中文 `MarkdownNote`。说明写入 8 条完整测试提示词、单分支切换步骤、LoRA 选择方法、官方采样参数和比较节点使用说明。

- [ ] **Step 2: 生成 MOSS 分支**

使用 `UNETLoader`、`CLIPLoader(type=moss_image)`、`VAELoader`、`Lora Loader (LoraManager)`、提示词拼接、`CLIPTextEncode`、`EmptyFlux2LatentImage`、两个 `KSampler`、两个 `VAEDecode`、两个 LoRA Manager 保存节点和一个比较节点。参数为 25 步、CFG 2.5、`er_sde`、`simple`。原采样器连接原始 MODEL，LoRA 采样器连接 LoRA MODEL，二者共享正负条件和 latent。

- [ ] **Step 3: 生成 Krea2 Turbo 分支**

采用相同双图结构，但使用 `EmptyLatentImage`、`ConditioningZeroOut`，参数为 8 步、CFG 1、`euler`、`simple`。该分支节点保持启用，作为默认测试分支。

- [ ] **Step 4: 生成 Qwen Image 2.1 分支**

采用相同双图结构，但使用 `TextEncodeQwenImage21` 同时产生正负条件，并使用 `EmptyLatentImage`，参数为 25 步、CFG 1、`euler`、`simple`。

- [ ] **Step 5: 设置分支隔离和画布布局**

将 MOSS 与 Qwen 分支的执行节点设为禁用，说明节点保持可见。三条分支纵向分组，左侧为说明与控制，中间为加载和采样，右侧为保存与比较；连线不跨接不同模型分支。

- [ ] **Step 6: 静态校验交付 JSON**

运行 Python 校验：JSON 可解析；节点和链接 ID 唯一；每条链接的源/目标节点与插槽存在；输入类型匹配；两个采样器除 MODEL 外共享种子、步数、CFG、sampler、scheduler、latent 和 conditioning；说明文本恰好包含 8 条编号测试提示词；默认启用分支仅为 Krea2。

### Task 3: 导入与低负载端到端验证

**Files:**

**Interfaces:**

- Produces: 三条分支各自的两次成功采样结果，以及无缺失节点、无断线的导入检查。

- [ ] **Step 1: 浏览器导入检查**

在临时实例中打开交付工作流，确认节点未显示缺失、说明节点可读、三组比较节点及连线存在。记录浏览器控制台中的工作流相关错误；无关插件警告单独说明。

- [ ] **Step 2: 转换三条验证执行图**

从交付 JSON 分别提取每条分支及其必要上游，保持节点类型和 widget 不变，仅把宽/高改为 256、步数改为 1，输出改为保存到临时验证前缀。每条执行图同时包含原模型和 LoRA 两个采样/解码/保存链。

- [ ] **Step 3: 验证 MOSS 分支**

通过 `/prompt` 提交 MOSS 验证图，轮询对应 history，确认执行成功且两个输出图像记录存在；失败时保留完整错误并修正交付图中对应的结构问题。

- [ ] **Step 4: 验证 Krea2 Turbo 分支**

以同样方式提交 Krea2 验证图，确认两个输出图像记录成功返回。

- [ ] **Step 5: 验证 Qwen Image 2.1 分支**

以同样方式提交 Qwen 验证图，确认两个输出图像记录成功返回。

- [ ] **Step 6: 复核交付文件并清理**

重新运行 Task 2 的静态校验，确认交付默认值未被验证覆盖。关闭本次启动的 ComfyUI，确认验证端口不再监听，删除独立临时目录中的 API prompt、日志和验证输出；保留交付 JSON、设计文档和计划文档。检查 `git status`，不触碰其他既有改动。
